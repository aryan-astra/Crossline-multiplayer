# Source A audit: STREETS / Crowd Command

Audited original `multiplayer-role-based-simulation-game` read-only on 2026-10-22. Findings below are verified from source inspection, not claimed runtime or performance results. No dependency scripts or source executables were run during this audit. All supplied files were inspected; no tests, README, lockfile, public directory, migrations, LICENSE, or CI were supplied.

## Architecture and dependencies

Actual branding: STREETS: Crowd Command in `src/app/page.tsx:151` and `src/app/layout.tsx`. Package name remains `nextjs-postgresql-template`. Next.js 16.2.6 App Router, React/ReactDOM 19.2.6, TypeScript 5.9.3, Tailwind4.1.17/PostCSS8.5.8, ESLint9.39.4, Drizzle0.45.2/DrizzleKit0.31.10, pg8.20.0, dotenv17.3.1, lucide-react^1.61.0. Only lucide is a floating dependency; no lockfile establishes reproducibility. No package manager/runtime policy. Scripts invoke ordinary Next/ESLint/tsc with no custom installation scripts. Dependencies themselves have not been license/vulnerability audited here.

`app/page.tsx` owns registration, callsign profile in localStorage, home/location/role/game screen state; a single route `/` renders all screens. `components/GameScreen.tsx` (689 lines) mixes network snapshots, keyboard/mouse handling, RAF driver, UI panels, wallet/bets/orders and round reporting. Rendering and simulation are separately placed in `game/render.ts` and `game/engine.ts`, with map geometry/types split, which is useful but not a fully isolated architecture because `World` also contains cameras, player wallet and presentation state. Four API route groups depend on PostgreSQL through `db/index.ts`.

## Implemented subsystems and strengths

- Menus: callsign entry, Delhi/Paris location cards, four roles, police career rank and client military lock at ten detentions; leaderboard. Game has event feed, minimap, role HUD, market sparklines, inspectable agent traits, roster, command, funding, bet and round summary panels. Native buttons generally provide basic keyboard access.
- Coordinates/maps: 2200x1500 world coordinates independent of canvas display size; Delhi walls/gates, rectangular shops and blocks, monuments, trees, roads, lawns, detention zones, depots/routes and spawns; Paris plaza and city blocks. Collision is circle-versus-rectangle ejection with world clamp (`maps.ts:224`). Distinct procedural architecture/monuments are drawn from actual map geometry, not promotional images stretched across play space.
- Rendering: Canvas2D, cached full-map ground texture, separate procedural people/trucks/crates/buildings/effects functions, world/camera transform, Y-sorted entities, overlaid tree canopies, gases and minimap. Procedural skin/clothes/sign/shield/rank variety, bobbing arms, speech bubbles, downed silhouettes and status rings. No image sprite animation/atlases/WebGL/audio, no renderer benchmarks.
- Simulation: five-minute local rounds, tension/morale/violence/property damage; finite duration bounds ordinary play. 34 protesters, 14 police, 4 military, 10 civilians (62 bots, despite marketing saying 60), optional local player. Entity cooldowns and think timers, removal filtering; projectiles/gases/effects expire, feed capped40, price history capped80. Player movement normalized diagonally, sprint and circle building collision; follower camera, spectator pan, bounded zoom.
- Protester AI (`engine.ts:233`): aggression, courage, discipline/chattiness plus cosmetic seed; thinks every0.35-0.65s, randomized rally targets, chanting, gas/threat flee, rock attacks on shops or nearby police. Supply stones affect likelihood but bot throws never consume stones. Repeated random choices do not constitute planning.
- Police (`engine.ts:298`): think every0.3-0.55s, ranked line holding, high-tension centroid push, batons, detention channel, discipline-weighted player order compliance, optional gas after supplies. Rank0-3 modifies detention rate and follower count. No actual independent commander-issued chain of command: all bots execute same rules; high-ranked bots are prioritized followers.
- Military (`engine.ts:389`): thinks every0.35-0.65s, checkpoint patrol, local active-violence/recent-throw rule, warnings and shooting. See defects below.
- Civilians (`engine.ts:417`): random wander/flee, reacts to violence/gas/military; high courage/morale may join protesters. No persistent spectator agent state: watcher feed is fabricated flavor.
- Economy (`engine.ts:565`): four local instruments mean-revert toward tension/violence/damage-derived targets with random noise; holdings and buy/sell, fixed-odds 60s event bets, local wallet, funding trucks and random crates. Bets have an in-memory status preventing repeated settlement within one world. This provides game design ideas only, no trustworthy economy.
- Supply vehicles: predefined waypoints, unload after3s, four random nearby crates grant stones/gas/shield/banner. Actual local movement and delivery logic exists.
- Persistence: `players` UUID, unique callsign, coins, detentions, rounds, creation; `presence` player UUID primary key, role/map/pose/time and map/time index. Real pg queries, not dummy persistence; DB setup is mandatory, yet migrations/bootstrap/seed/.env example absent.

## Critical verified defects

1. **Identity impersonation**: `/api/players` POST returns existing profile from callsign alone; no authentication, secret, session cookie or ownership evidence. GET publishes complete top rows including UUIDs. A callsign is enough to impersonate an existing profile.
2. **Arbitrary wallet/career writes**: `/api/players/[id]` PATCH blindly accepts coinsDelta up to100000, detentionsDelta up to500, roundsDelta up to50 per request for any UUID. Replay is unlimited; no idempotency key, authoritative match record, military permission, integer/finite checks, authentication or rate control. Float/NaN/invalid UUID can cause database errors. SQL values are parameterized so this is not evidence of SQL injection. LocalStorage profile is also trusted for role unlock.
3. **Presence is not synchronized multiplayer**: `/api/sync` stores browser-provided UUID, map, role and pose; `GameScreen.tsx:67-109` polls every1.6s and independently blends remote positions. Bots, attacks, arrests, health, map damage, commands, bets, market, supply and match clock are independently computed with Math.random in every browser. No rooms, shared authoritative simulation, protocol version, ordering, input sequences, validation, sessions or membership. Remote avatars can be locally hit/arrested and not report outcome. Same-map sessions from distinct rounds mix. Out-of-order HTTP responses and overlapping requests are uncontrolled. No presence-row deletion/TTL cleanup; query merely ignores records older8s. Unauthenticated requests can overwrite another identity, impersonate military, submit arbitrary/nonfinite pose, spam unlimited identities. API returns up to24 other rows without stable ordering.
4. **Renderer changes simulation**: `render.ts:433` decrements detention progress by0.008 per rendered frame. Arrest speed depends on frame rate and whether renderer runs; render-driven randomness also consumes same global RNG as gameplay. Seed fields do not seed random generator.
5. **Map state leaks across rounds**: `createWorld` uses `MAPS[mapId]` directly (`engine.ts:66`); stone hits mutate building hp/broken in shared singleton. Subsequent worlds retain destruction and can interfere when run headless in same process.
6. **Unbounded action farming and removed-player actions**: protester chant has no cooldown and adds2 earned coins and4 morale every press/repeat. `doAction:493` guards down/stun but not detained/remove. Detained player is eventually removed without respawn or clear player reference; actions can continue from stale reference, and camera remains attached. Military warning shot ignores cooldown. Repeated calls to profile PATCH amplify any local result without playing.
7. **ROE mismatch**: `roeValid:209` only checks protester active timers/notdown/notdetained. Player primary ignores warning prerequisite, tension and precise target aim and selects nearest non-detained protester; unauthorized shots intentionally fire with wallet fine. AI warning code checks target within260 but only marks within220, allowing perpetual warnings for targets221-260. AI `else if` directly trusts recent timer predicate; no line of sight/projectile occlusion. Bullet damage resolves against target ID regardless of later motion, detention/down state, intervening walls or target eligibility.
8. **Collision/navigation**: direct seek with no pathfinding/stuck recovery cannot route around walls/blocks/monuments. Civilian spawn jitter may place units inside buildings. Crowd separation after collision directly pushes coordinates without building/bounds correction (`engine.ts:766-784`), including remote/detained characters. Trucks do not collide at all. Monument drawings extend outside rectangular collision bounds (e.g. Samrat lateral arcs, Paris stepped pedestal); trees are visual-only. Endpoint ejection is not swept collision, so sufficiently large externally supplied motion can cross thin walls.
9. **State transition flaws**: nearest excludes remove/truck/crate but not down; several police filters target downed protesters, enabling detention of downed entities. Detention progress is stored on target, allowing multiple officers to accumulate together and interrupted channels leave progress until renderer slowly drains it; no officer ownership or explicit cancel reset. Detain handler does not independently guard repeated/removed/down targets. Timers process remove-marked entities until end-of-tick filtering. Order modes move/hold/line are structurally present but only move is exposed and all modes behave identically; replacing orders can retain old per-officer order; expiry cleanup only occurs at think ticks, with potential global order removal before an officer sees it. Military patrol moveTo executes only at think interval using frame dt, making movement much slower than intended. Civilian flee chooses random target, may flee toward danger; threat logic tests military.warnedT even though warnings live on protesters, so that military fear condition does not correspond to warning behavior.
10. **Time/determinism/complexity**: `Math.random` alias and random comparator shuffle, module global feedId, frame-variable dt clamped0.05 rather than fixed-step accumulation. Long frames/tab suspension lose simulated elapsed time. No seed injection/reproducibility. Approx O(N²) separation every frame plus repeated nearest/filter/sort scans in AI; Canvas redraws all geometry and sorts all entities with no viewport culling, DPR scaling, quality cap, instrumentation or measured budgets. Cached ground consumes2200x1500x4 (~13.2MB) before canvas overhead.
11. **Economy correctness**: funding accepts negative/nonfinite amounts; buy qty has no safe integer/finite validation; stake allows nonfinite, entities absent/down/removed and arbitrary type at runtime. Trucks/crates/bets not capped. `violent60` resolves everViolent lifetime flag, so already violent targets can generate easy wins, not a new event after wager. `free60` checks deadline state, not continuous60s freedom. Removed police/protesters cause lost bets even when event occurred earlier. Open bets placed near end never settle/refund. Holdings portfolio is displayed but is not included in persisted finish delta or liquidated, destroying value on exit. Watcher ambient feed claims transactions by named bots without wallets/actual debits, and only sometimes spawns a truck. No real-money integration present.
12. **UI/runtime/deploy**: no supplied `public` assets; `/img/title.jpg`, `/img/delhi.jpg`, `/img/paris.jpg` references necessarily lack local files. Fixed300px sidebar/right inspector/220px minimap/action bar overlap on narrow screens; no touch movement, input blur reset or accessible canvas equivalent. Icon-only close lacks label, input has no explicit label, locked role button lacks semantic disabled. Animation lacks reduced-motion preference. Google Fonts CSS import introduces external dependency. Render loop continues after round over, repeatedly setsEnded and still syncs. Async sync not aborted on unmount, errors silently swallowed and online count starts as1 even offline. No leave/abandon action before round end. `db/index.ts` throws on missing DATABASE_URL at import outside health catch; production build/runtime may fail before graceful health response. PostgreSQL-only API requires hosting supporting long-lived pg connectivity. drizzle config embeds a local development password URL; no evidence it is a live secret, but replace with env-based sanitized example. No migrations establish table existence and unique callsign select-then-insert races may throw.

## Menu, routing, UI, input

Units use coherent procedural shapes, role palettes, helmets/shields/rifles/flags, selection markers and movement bobbing. ## Simulation and determinism

`Game` exposes `tick(dt)` and cleanly excludes React and document use. Initial population is 24 police (four squads of six), 78 protesters, five military, 12 civilians, plus an optional player. Match duration is 360 seconds. Timed gas, supply convoys, market ticks and end conditions are implemented. Feed is capped at 60, toasts at four, market history at 760; gas/projectiles/pings/crates/completed vans expire. Unit count is bounded by initial spawn. Watcher funding can create many vans before completion, but no measurement of a practical abuse ceiling was performed.

The engine header claims deterministic fixed-step simulation, but GameClient invokes one variable `tick(min(0.05, elapsed))` per animation frame. No accumulator exists; hidden/slow frames drop elapsed time, while damping/smoothing constants are applied per call, changing behavior with refresh rate. Engine/AI/gaussian helper call Math.random extensively; names use a random sort comparator; match code uses Date.now and randomness. There is no seed injection or reproducible harness. `RANK_ANNOUNCED` is mutable module-global state across Game instances. `checkEnd` uses active/occupancy arrays captured before this tick's detention/removal; results can lag a step.

Recommendation: preserve independent engine API but make RNG world-owned, use fixed simulation steps and instance-local state, and test equality for same seed/input sequence. Rendering animation may remain wall-clock-local.

## AI decision systems and complexity

`commanderThink` reevaluates every 2.5 seconds. It computes overall/violent crowd centroids, leaves squad zero guarding detention, rotates charges after 75 seconds, otherwise forms a loose cordon. It respects player orders for 20 seconds. Rank unlocks are 3 detentions for command and 8 for military; rank thresholds are 0/3/6/10/16. These differ from Source A and require one explicit shared policy.

Formation slots are mathematically centered, spaced by 26 units along the perpendicular to centroid→order direction (`ai.ts:111` onward). This is a verified useful algorithm; however centroid-relative heading can change rapidly near the destination, so formation stability needs testing.

Per-unit brains run each simulation tick, rather than at a separate scheduled decision cadence. A 90-unit spatial hash limits neighbor searches (`engine.ts:171` onward). Each police brain still filters the entire unit array for squad members each step, and custody uses linear finds; complexity includes O(P×N) work. Commander is O(N + squads×N). Collision is O(N×colliders). This is bounded for baseline populations but needs measurement before scaling.

Protesters have courage/aggression/speed/morale, organizers boost nearby morale, flee gas by four directional samples, flee chasing police/aiming military according to courage, leave at low morale, probabilistically throw, and march with seek/cohesion plus engine separation. Rally milling uses deterministic golden-angle personal offsets. These are explainable heuristics rather than learning. There is no independent stress variable, navigation mesh, pathfinding, line of sight or trapped-agent recovery. Civilians select random city waypoints or a fixed per-ID escape spot; the escape destination is not actually chosen for safety despite the name `far`.

Verified dimensional bug: police intercept uses `prey.vx * lead * 60` and similarly vy (`ai.ts:211`) while engine integrates vx/vy directly as world units per second. Pursuit leads are exaggerated by 60×. Seek velocities persist at grabbed protesters until later damping/separation, allowing drift while a bot is channeling. Police fallback executes before grab handling, so becoming outnumbered can interrupt the officer's brain without cleanly releasing the custody reference. No channel range recheck exists for bot grabbing.

Recommendation: preserve corrected formation math, golden-angle spreading, spatial hash, personality thresholds and explicit states as selected algorithms. Introduce route validation/obstacle routing and fail-safe transition cleanup before wholesale reuse. Avoid copying the B FSM unmodified.

## Collision/navigation defects

All buildings have rectangular colliders; trees/palms, statue, landmark instruments, fountain, kiosks/metro, barricades and boundary walls have matching circle/rect collision approximations (`engine.ts:82–100`). Axis-minimum penetration correction runs after movement and world coordinates clamp to bounds. This is superior to treating decorative geometry as the whole playable map.

There is no swept collision: large steps can tunnel through thin walls. Circle collision skips exactly centered overlaps (`d > 0.01`), leaving a center-spawned unit inside. Sequential correction can push a unit into an earlier collider. No spawn clearance is applied before first tick. Dragged units directly inherit positions and skip collision; vehicles follow routes without any collision checks. Steering simply pushes toward a target, so blockers can indefinitely trap a bot, escort or command formation. Some goals are inside solids: Paris civilian spot (1120,100) lies inside building (1010,20,180,130); Paris police spawn (330,480) overlaps the barracks ending at x=340. These are concrete map-coordinate defects.

## Detention and military interactions

Police select eligible targets by charge/violence/unrest, channel grabs for 1.4 seconds, allow stochastic struggles with courage/backup, escort at 55% speed, then increment detentions at the van. Player must stand still for cuffing. However player-protester `tickPlayer` (`engine.ts:561–569`) clears `grabbedBy` unless `cop.grabbing` is already complete. Bots assign `grabbedBy` before completing their 1.4-second channel, so the player clears the pending grab every tick and generally cannot be arrested through that path. Repeated E while already channeling can replace target without releasing the old target immediately. Departed protesters reuse `detained=true` without incrementing detention stats, so personal “evades detention” offers resolve incorrectly for voluntary departures.

`militaryFire` is a shared bot/player rule gate requiring active warning, violent flag, unrest>55, range≤260, and target not down/detained/grabbed. Bots aim 1.2 seconds; player targets under mouse. Shots down nonlethally, then after eight seconds auto-detain and increment global stats. This shared validation pattern is worth retaining. The function does not itself verify shooter role/status or target faction, so it is not a sufficient network trust boundary; no obstacle/line-of-sight gate exists. Player action methods don't uniformly reject detained/down actors. Military player scoring counts global lawfulShots/warnings made by bots as the player's own. Supply collection affects nearby friendlies' shields/morale/flags, not abstract money transfers.

## Networking, persistence, economy and security

No WebSocket, WebRTC, room server, remote player snapshot stream, authoritative tick, sequence number or multiplayer membership exists. Every browser constructs an independent random Game with an independent matchCode. Only profile creation, leaderboard fetch, bets and end-result persistence contact APIs. It must be described as a local single-player simulation with unsafe profile/economy endpoints, never synchronized multiplayer.

Schema has players, match_results, bets, market_ticks. Names are unique and foreign keys exist, but there are no unique match/idempotency keys, enums, transaction ledger, nonnegative balance constraints, match-membership records or migrations. No database lifecycle or credential ownership is documented.

Critical client trust defects:

- Every endpoint accepts public playerId/name with no session, ownership check or authorization. Anyone can alter another known ID's career or wallet.
- POST match accepts arbitrary detentions, score, rank, creditsDelta, role, outcome and settlement won booleans. Users can grant military unlocks, fabricate results and mint virtual funds.
- POST bets accepts client odds with only finite-number validation, so enormous or negative odds are accepted. Label/pick/matchCode are arbitrary with no authoritative offer/match lookup or cutoff.
- Bet debit is read-then-write followed by insertion outside a transaction. Parallel bets can lose debits or leave balance changes without bets.
- Match settlement separately reads open bets then updates; concurrent finish requests can both pay a bet. Career and credits updates also lose concurrent writes. Replaying a match always adds score/progression/credits and another result because match_results has no matchCode key.
- Settlement checks owner and open status but not bet.matchCode, allowing unrelated match results to settle old bets.
- `endSentRef` is browser-local one-shot state and provides no server idempotency. It is set before request succeeds, so transient errors have no retry.
- Trading and funding use local wallet deltas, while placing a bet resets displayed credits from DB. Local trading proceeds may fund a visible balance the betting API does not recognize; bet responses can overwrite pending local debits. Final client creditsDelta is trusted without validating this history.
- JSON bodies and settlement counts are not size-limited; numeric values lack safe-integer/bounds rules. Database errors have no uniform application handling.

`GET player` exposes entire profile; `GET match` returns public claimed rankings; `GET bets` returns a known player's bets. SQL use is through ORM expressions rather than interpolated raw user SQL, a useful existing strength that does not solve authorization. No real-money integration appears.

Recommendation: do not migrate these APIs into production. Initially keep economy/progression explicitly local practice, or disable persistence writes. Future authoritative rooms must own identities, inputs, outcomes and ledgers; transactions, uniqueness and conditional settlement are required. Retain economics only after replacing client authority. Do not infer secure persistence from PostgreSQL's presence.

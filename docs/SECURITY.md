# Local security boundary

The server validates versioned messages, finite bounded inputs, integer prices/quantities, roles and transaction ownership. Cookie tokens are random and stored only as hashes; cookies are HttpOnly/SameSite Strict. HTTP writes and socket upgrades require same origin. Requests and sockets have rate, payload, buffer and connection limits. A replaced tab stops reconnecting, preventing connection fights.

The 23 October 2026 dependency audit reports zero vulnerabilities in production dependencies. The full audit reports five High findings in the development-only Next ESLint dependency chain through `braces` (GHSA-vfj7-8cjw-p6xm). The advisory lists no patched release; npm's forced fix downgrades `eslint-config-next` to14.2.35, so it was not applied. These packages are omitted from production installs; recheck the chain after an upstream fix.

Authoritative events own detention/death/objective rewards. Death/custody cannot be cleared by changing role/map or reconnecting. Military eligibility/expiry and five active military slots are server validated. Monetary mutations use prepared statements, safe integers, transactions, durable receipts and ledger keys. Repeated IDs return the prior result; altered payloads fail. No balance/outcome increment endpoint exists.

Guest identities do not prevent alternate accounts or coordinated market manipulation. Clearing the cookie loses account access. Local HTTP is unencrypted; use TLS and an audited origin/proxy configuration for internet deployment. Snapshots are interest-filtered, not a complete fog-of-war confidentiality model. Database/ledger history grows on disk and needs backups/retention policy. Connection admission caps are safety limits, not measured hosting capacity. No privileged test commands are exposed over the network.

# Networking

## LAN and online authorities

`npm run start:lan` starts private-network play using `data/crossline.sqlite` and the existing guest cookie. `PUBLIC_ORIGIN=https://your-host npm run start:online` (set the variable separately in PowerShell) uses `data/crossline-online.sqlite` and a distinct `crossline_online_session` cookie. Set different ports when running both on one host. `/api/connection` reports the actual mode. `ONLINE_URL` optionally links the LAN title screen to a configured public authority; an unconfigured Online button stays disabled. These are separate server processes/stores, not browser-owned simulations or arbitrary room codes.

LAN checks the actual TCP peer for private/link-local/loopback addresses and ignores forwarded client-address headers. This is a network convenience boundary, not authentication against a malicious LAN peer. A reverse proxy or tunnel can make public visitors appear local: never publish the LAN process that way. Use online mode with HTTPS/WSS and a configured origin. Same-site cookies and all existing command validation still apply. Disconnect immediately cancels Book participation.

Visual prediction uses the server's movement/collision helper with at most 150 ms lead. Authoritative snapshots reconcile position; clients cannot predict transactions or capture/combat outcomes. This is not full input replay reconciliation.

The custom Node server owns two location simulations targeting 30 fixed steps/second. It runs at most one step per timer callback so slow ticks yield to network I/O rather than accumulating catch-up work. Under overload the shared simulation clock slows; the transport overload regression verifies that scheduling boundary and an HTTP response. Changed browser input is capped at 20Hz; unchanged input is repeated every 250ms to keep the server-side input lease alive, which expires after half a simulation second. Snapshots target 10Hz; browsers never advance independent public worlds. One active socket per guest identity prevents duplicate bodies; use separate browser profiles/private windows for multiple players.

GET /api/session creates/resumes a guest; POST changes its name. Cryptographically random tokens are stored hashed and sent in HttpOnly SameSite=Strict cookies. Origin checks protect writes/upgrades. GET /api/health and /api/leaderboards expose public data. /socket uses version1, monotonic per-connection sequence numbers and bounded request IDs. Inputs/actions are validated; stale sequences, role bypasses and overdrafts fail. Economic receipt fingerprints survive reconnect/restart and reject changed payloads under reused keys.

Transport bounds payload size, message rate and outbound buffering, checks heartbeat liveness, expires input after half a simulation second, and saves/removes disconnected characters after a grace period. Reconnect restores identity without a fresh wallet or duplicate body. Settings stop local input, not public time.

The input budget uses a monotonic token bucket: 60 messages/second with at most 120 queued messages in a burst. This tolerates short network or event-loop stalls without removing the flood bound. Non-input actions retain their separate 10/second limit, and three malformed frames still close the connection. The transport test accepts an 80-message queued burst and rejects a further flood.

The browser keeps a bounded queue of unacknowledged trades, predictions and supply funding while the game screen remains open. It shows a waiting-for-receipt notice, replays these commands after reconnect with their original request IDs, and removes them on an explicit acknowledgement or rejection. Map-specific predictions and supply requests are not replayed into a different city; the player receives a check-wallet/history notice instead. The server's durable operation receipts prevent duplicate effects if a response was lost after commit. Exiting the game clears this in-memory queue; profile balances remain server-owned and can be read again on re-entry. This is reconnect recovery, not an offline order book or guaranteed execution at a previously displayed quote.

Active roles receive nearby entities; spectators receive a full location for observation. Snapshots include authoritative bots, objective, deliveries and outcomes. Police receive one server-assigned wanted dispatch and the target entity even outside ordinary interest range; assignments are scoped to a map and move to another officer when a player disconnects. Interpolation is visual only.

Each socket receives a versioned `map` frame before its compact snapshots and whenever its active map changes. New clients opt in with `supportsDeltas: true` on join; legacy clients retain full compact snapshots. For opted-in clients, the first update is a full snapshot; later updates are deltas keyed to the prior tick, including changed/removed world fields, entity upserts/removals, ordering and new events. The browser applies a delta only to its matching base tick and map; if it cannot, it reconnects to obtain a fresh full snapshot and map. Repeated snapshots include the map ID and building health/broken states instead of static geometry. The browser reconstructs full render snapshots from that cache; reconnect obtains geometry again. WebSocket compression is **disabled**: a browser trace reproduced input sequences hundreds of messages ahead of server acknowledgements with compression negotiated. A fresh uncompressed connection produced an authoritative position update in 86ms in the same local keyboard test. This sample is not an internet latency guarantee. At most one snapshot write may remain unfinished per connection; superseded updates are skipped instead of queued. Acknowledgements and durable financial receipts are not discarded. Static-map omission and entity deltas reduce traffic without compression. Sustained multi-client bandwidth measurements are required before public deployment. Re-enabling compression needs a continuous small-input browser benchmark, not just a snapshot-size ratio test.

Join commands may select the validated `gathering` or `approach` entry area. The server resolves coordinates and collision clearance only for a newly spawned character. Rejoining cannot move an existing character, escape custody or reset a wallet through area selection.

Guest cookies are bearer identities. Clearing cookies creates another guest; no verified-human identity, account recovery, anti-Sybil system or public-internet abuse guarantee exists. Run exactly one host process against the world database. Behind a TLS proxy, set `PUBLIC_ORIGIN` to the exact public HTTP(S) origin; the entry point also accepts Render's server-provided `RENDER_EXTERNAL_URL`. This configured origin controls POST/upgrade validation and Secure cookies. Arbitrary forwarded headers are never trusted; Cloudflare edge headers do not replace explicit origin configuration. Local development defaults to the direct socket protocol and Host. HTTPS and public-internet abuse hardening remain deployment requirements. Tests exercise real two-socket replication and persistence; see VALIDATION.md for browser evidence.
